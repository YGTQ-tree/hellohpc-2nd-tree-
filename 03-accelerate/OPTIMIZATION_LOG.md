## 2. 已完成的实验与结论

- `Agent 辅助答题` 无限制；但不得打表、不得攻击评测、不得把计算挪出计时区间、不得在登录节点跑重负载、赛后 Code Review 需保留可读原始源码。

### 2.2 性能瓶颈定位

在 `kp_run` 32 核上用独立 C 微基准拆解工作量（Q=98304、C=10240、D=32，共约 10.06 亿个 (q,c) 对）：

| 内核 | 时间 |
|---|---:|
| 原始风格“只算平方距离+点积” | 约 1550 ms |
| 标量 `expf` 额外开销 | 约 +520 ms |
| 标量 `sinf` 额外开销 | 约 +750 ms |
| 两者同时 | 约 1700 ms |

结论：

1. **标量三角函数（尤其 `sinf`）和标量点积/规约是主要成本。**
2. Kunpeng 上 GCC 10.3 不会对 `expf/sinf` 自动向量化，需要自己写 NEON 向量数学或减少调用。
3. 原始“每个 q 重扫全部 centers/trig_vec”的访存模式不是首要瓶颈，但它配合标量规约放大了成本。

### 2.3 已实现的关键优化原型

`exp/` 目录位置（本地与 `legion:~/hellohpc-contest/03-accelerate/exp/`、`arm:~/hellohpc-03/03-accelerate/exp/`）：

- `v1_inverted.py`：c 外层、q 内层、块内 q 私有；双精度累加。large-b 约 1.7 s，正确性通过。
- `v2_neon.py`：ARM NEON 手写内核。q 方向用 4-lane 向量，避免每对 (q,c) 的水平规约；自写 4-lane `exp4/sin4` 多项式；r/p 用 float，输出用 double 累加；points 转置缓存。**kp_run 32 核实测 large-b 约 0.84 s，公开正确性通过。**
- 修复了两个关键问题：
  1. **转置矩阵行距必须加 padding**（`stride = Q + 16`）。原 `Q` 为 64 KiB 的整数倍，导致 32 行数据全部映射到同一批 L1 set，严重冲突，修复前约 4.7 s，修复后约 0.84 s。
  2. NEON Horner 多项式必须写成 `p = fma(c, p, x)`（`vfmaq(a,b,c)=a+b*c`），不能写成 `vfmaq(p,x,c)`，否则全错。

### 2.4 精度现状与根因

用 `public-large-b.ref.txt`（`atol=1e-5, rtol=1e-4`）比较：

| 版本 | 最大误差率（误差/容差，越小越好） | large-b 时间（8 核相对） |
|---|---:|---:|
| 原始 `src/solver.py` | 0.468 | 较慢 |
| `v1_inverted` | 0.593 | 慢 |
| `v2_neon` | 0.816 | 最快 |
| `v2_dot4`（d 方向 4 个独立累加器） | 0.626 | 几乎不慢 |
| `v2_dot8`（8 个累加器） | 0.609 | 略慢 |
| `v2_dot16` | 0.611 | 更慢 |
| `v2_mathlibm`（用 libm 替换自写三角函数） | 0.819 | 更慢 |

结论：

1. **误差几乎全部来自 float 点积/距离的累加**，不是自写三角函数。
2. 在 Python 双精度模型上，如果 r/p 是“先精确计算再舍入到 float”，误差率可降到约 **0.098**；如果只是更换三角函数的实现，误差不变。
3. 继续增加累加器数量收益递减（4→8 基本持平），可能需要补偿求和或更高精度方案。
4. 用完整 double 做 r/p + double 向量数学虽然精度极高，但微基准约慢 3 倍以上，可能牺牲 large-a 的满分，暂未采用。

### 2.5 c 分块 / q 展开的访存优化

为避免每个 q 反复从 L2/L3 重读 `xt`，实验了“c 分块 + q 展开”：

- 每次处理 CB 个 c 和 UQ 个 4-lane q 向量，x 只 load 一次并复用给 CB 个 c。
- 8 核相对测试（`kp_interact`，非正式绝对时间）：
  - 标量基线 `cb1_q1`：约 2041 ms
  - 最优附近 `cb3_q4`：约 994 ms
  - `cb2_q8`：约 1001 ms
  - `cb4_q4`：约 1013 ms
- 完整内核（含自写向量数学、double 累加）8 核测试：
  - `cb3_q4`：约 1599 ms
  - `cb2_q4`：约 1626 ms
  - 参考 `cb1_q4`：约 2694 ms

预计合入后 32 核 large-b 有机会进入 **0.5 s 档**，但**尚未在 32 核 `kp_run` 上验证**。
