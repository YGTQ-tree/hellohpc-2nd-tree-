# 04-cheatsheet：Bitmatrix 优化指导 Skill

## 1. 这题的目标

这题不直接提交优化后的 C++ 算子。我们提交一份 `SKILL.md`，由比赛平台里的 Agent 阅读后，再让 Agent 在限定轮数与时间内优化一个算子。可以选择 FFT 或 bitmatrix，也要选择模型。最后是否得分，取决于 Agent 最终留下的代码是否正确、运行多快，以及指导资料占用了多少 tokenizer token。

我保留仓库原有的 `bitmatrix` 与 `qwen3.8-27b` 选择。公开题面显示，FFT 需要实现完整复数变换，数值结果还要满足浮点容差；bitmatrix 则是精确整数计数。对初学者来说，bitmatrix 的接口、正确性检查和计数器优化步骤更直接，也更容易在有限轮数内验证。

## 2. 从朴素代码找出重复工作

bitmatrix 的矩阵按行保存，每个 64 位整数表示一行里连续 64 列的 0/1。掩码决定哪些行参与计数。初始代码按列循环：每算一列，都重新检查每一行是否被选中，再读取对应位。于是同一行的掩码检查和矩阵字会随着列重复处理很多次。

更合适的方向是按行扫描。对一个 64 位矩阵字，64 个位分别代表 64 列；可以用若干个 64 位“计数位平面”同时表示这 64 列当前计数的相同二进制位。遇到一个被选中的矩阵字，就用 XOR 和 AND 传播进位，将这 64 个列计数都加一。最后把各个位平面还原成每列的整数计数。

最大 `N` 为 8192，所以任一列计数在 0 到 8192 之间，14 个二进制平面足够表示。Skill 特别要求检查全零掩码、全选掩码和最大规模边界，以发现位宽或进位错误。

## 3. Skill 如何引导 Agent 工作

`SKILL.md` 先让 Agent 只查看算子任务说明、头文件与初始实现，并限定只改算子实现和编译选项。随后要求先通过候选测试建立正确基线，再逐项应用行扫描与位平面计数。遍历掩码中被选中的行时，可用置位最低位索引指令（如 `ctz`）跳过未选行；每个改动后重新验证。

测量顺序也写入 Skill：正确候选才做性能分析，再跑基准比较；编译选项尝试必须通过正确性和性能验证。收尾的四轮不再探索，而是恢复并重测最快的正确代码与相应编译选项，因为评测器不会替 Agent 自动回滚。

## 4. 规则与提交边界

提交目录使用题目规定的 `submission.yaml`、`SKILL.md` 和可选 Markdown 参考资料。Skill 中只写通用方法和工作流程，不放完整算子实现、可执行文件或正式答案。评测器的接口、测试、计时和评分逻辑均不修改。公开说明要求资料不超过 1200 tokens，且超过 400 tokens 后会逐渐降低长度倍率；本提交没有额外 `references/`，以减少长度成本。
